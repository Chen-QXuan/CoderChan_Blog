    computed()

    # computed()

    computed 的出现，主要是为了解决 template 里面复杂的逻辑写法。

    computed 可接受一个 getter 函数作为参数，并返回一个带有 value 属性的对象，该 value 值也就是传入 getter 的返回值。

    computed 是个 “懒” 东西来的，若是你无需去访问它的时候，它甚至都不会运行。

    由于它的懒，也造就了它强大的 缓存 机制，若 getter 函数里面所依赖的响应式对象没有发生改变的话，懒惰的 computed 是不会再次调用的，它会将上次计算出来的结果，继续拿出来给你。

    • 思路：
      • 访问该计算结果需要通过 .value 去访问，那么可以像创建 ref 一样，创建个 class；
      • 当访问的时候再调用 getter；
      • 通过一个“开关”变量来判断，此次访问是否需要重新运行 getter。
    function computed(getter) {
  return new ComputedRefImpy(getter)
}

class ComputedRefImpy {
  // effect对象
  public _getter: any
  // 开关变量
  public _dirty: boolean = true
  // 存储缓存结果
  public _value: any
    
  constructor(getter) {
    // 1、将getter当做effect参数，使用effect是因为能够监听到响应式对象的set操作。
    // 2、之所以是通过创建实例来使用effect，而不是直接调用，是因为刚调用computed时，getter是不会立即执行的。
    // 3、传递scheduler => 响应式对象set，不会触发getter，而是修改开关变量即可，等到.value再触发
    this._getter = new ReactiveEffect(getter, () => {
      !this._dirty && (this._dirty = true)
    })
  }

  get value() {
    // 若响应式对象没有set, 则每次调用都从缓存里拿数据。而不是每次都调用getter
    if(this._dirty) {
      this._dirty = false
      // 执行run也就是执行getter。在effect的源码实现里有详细介绍！
      this._value = this._getter.run()
    }
    return this._value
  }
}

    最后引用官爷的劝说：

    计算属性的 getter 应只做计算而没有任何其他的副作用，这一点非常重要，请务必牢记。举例来说，不要改变其他状态、在 getter 中做异步请求或者更改 DOM！一个计算属性的声明中描述的是如何根据其他值派生一个值。因此 getter 的职责应该仅为计算和返回该值。
